# 维护与目录说明

本文档说明当前项目的运行目录边界，以及可以安全执行的日常维护操作。目标是清理可再生缓存，同时不影响用户素材、项目、成片、草稿、配置或任务断点。

## 目录职责

| 目录 | 用途 | 维护规则 |
|---|---|---|
| `uploads/` | 用户导入的视频、音频、图片等素材 | 不通过维护脚本删除。仅在界面中确认素材不再被项目引用后删除。 |
| `output/` | 成片、配音、字幕、预览和剪映草稿包 | 用户交付物。不得批量清空。 |
| `exports/` | 视频编辑器导出的项目文件 | 用户导出物。不得批量清空。 |
| `database/` | SQLite 项目、素材与任务元数据 | 不得手动删除或替换数据库文件。 |
| `logs/` | 应用诊断日志 | 排查问题前保留；不作为常规清理目标。 |
| `temp/` | 分析缓存、处理中间文件和断点恢复数据 | 任务运行或待恢复时不得清理，尤其是 `checkpoints/`。 |
| `storage/` | 配音引擎配置兜底、试听与压缩包临时存储 | 由对应功能按需维护，不要直接整目录删除。 |
| `outputs/` | 兼容旧配音输出路径 | 当前仍由配音相关流程兼容使用，不合并、不删除。 |
| `models/`、`resource/` | 模型权重、字体和处理资源 | 不作为缓存处理；升级时按模型或资源说明单独维护。 |

`temp/jjyb_verify_68d2m8ek` 当前不可访问，维护操作会跳过它。不要为了清理而强制取得权限或删除该目录。

## 安全清理

项目提供 `scripts/maintenance.py`，默认只列出候选项。它的清理范围严格限制为 `backend/`、`frontend/`、`scripts/`、`tests/` 中的 Python 字节码和测试工具缓存：`__pycache__/`、`*.pyc`、`*.pyo`、`.pytest_cache/`、`.mypy_cache/`、`.ruff_cache/`、`.coverage`。

先预览：

```powershell
py -3 scripts/maintenance.py
```

确认列表只含缓存后再执行：

```powershell
py -3 scripts/maintenance.py --apply
```

该脚本不会扫描或删除 `uploads/`、`output/`、`outputs/`、`exports/`、`database/`、`logs/`、`temp/` 或 `storage/`。

## 日常验证

进行源码维护后，优先执行以下检查：

```powershell
py -3 -m py_compile frontend/app.py backend/api/material_routes.py
py -3 -m unittest discover -s tests -v
py -3 scripts/check_system.py
```

`check_system.py` 会检查依赖、FFmpeg、路径、配置和端口状态。它用于诊断，不替代真实素材的剪辑流程验证。
